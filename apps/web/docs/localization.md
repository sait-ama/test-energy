# Локализация в проекте

## Общие принципы

Все строки текста в проекте должны быть вынесены в файлы локализации (`i18n/*.json`). Это обеспечивает:
- Единообразие текстов
- Возможность перевода на другие языки
- Централизованное управление текстами

## Структура ключей

Ключи в файлах локализации следует писать в `snake_case` с разделением по логическим блокам:

```json
{
  "pages": {
    "home": {
      "title": "Главная страница"
    },
    "profile": {
      "title": "Профиль пользователя"
    }
  },
  "reusable": {
    "empty_states": {
      "empty": "Пусто"
    },
    "actions": {
      "save": "Сохранить",
      "delete": "Удалить"
    }
  }
}
```

## Использование в компонентах

### Импорт переводчика

```tsx
import { useTranslations } from 'next-intl';

export const MyComponent = () => {
  const t = useTranslations('reusable.empty_states');
  
  return (
    <div>
      <button>{t('actions.save')}</button>
      <FlatList.Empty text={t('empty')} emoji="🎴" />
    </div>
  );
}
```

### Использование с параметрами

```tsx
import { useTranslations } from 'next-intl';

export const MyComponent = ({ name }) => {
  const t = useTranslations('pages.title-detail');
  
  return <h1>{t('title', { name })}</h1>;
}
```

## Популярные значения

Старайтесь использовать существующие ключи для часто встречающихся значений:

- `reusable.empty_states.empty` - "Пусто"
- `reusable.actions.back` - "Назад"
- `reusable.actions.save` - "Сохранить"
- `reusable.actions.delete` - "Удалить"
- `reusable.actions.cancel` - "Отмена"

## Правила именования ключей

1. Используйте `snake_case` для ключей
2. Для ключей на верхнем уровне используйте логические группы: `pages`, `reusable`, `form`, `errors` и т.д.
3. Сокращайте ключи до общего смысла, избегайте длинных путей
4. Для полей форм используйте структуру `form.placeholders.<field_name>` и `form.labels.<field_name>`
5. Для ошибок используйте структуру `customErrors.<category>.<error_type>`

## Переиспользование

Переиспользуемые значения должны храниться в `reusable.*`. Сюда подходят абстрактные ключи, такие как:
- Действия (купить, получить, сохранить)
- Состояния интерфейса (пусто, загрузка)
- Часто используемые сообщения (подтверждение, успех, ошибка)

Стремитесь переиспользовать одинаковые тексты через общие ключи:
```tsx
// Неправильно
<Button>Назад</Button>

// Правильно
<Button>{t('reusable.actions.back')}</Button>
```

## Структура локализации по разделам

Для функциональных разделов приложения создавайте собственные ключи:

```json
{
  "character": {
    "form": {
      "labels": {
        "character_name": "Имя персонажа",
        "alt_name": "Альтернативное имя/название"
      }
    }
  }
}
```

## Миграция с hard-coded строк

При обнаружении hard-coded строк в проекте:

1. Добавьте ключ в соответствующий раздел `ru.json`
2. Импортируйте `useTranslations` в компонент
3. Замените hard-coded строку на вызов функции переводчика
